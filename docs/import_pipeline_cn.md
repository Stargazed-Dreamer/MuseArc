# 导入流程与分支（当前实现）

本文档描述当前导入链路的执行顺序、审查触发条件与用户可操作分支。

## 1. 扫描阶段

1. 扫描来源目录，拆分为音频文件和歌词文件。
2. 读取恢复状态（如有），已处理文件跳过。
3. 初始化文件状态列表（待处理/处理中/已归档/待审查/已跳过）。

## 2. 音频阶段

1. 音频探测（PyAV）：
   - 读取时长、采样率、声道、码率、标签、封面基础信息。
   - 探测失败进入 `文件异常` 审查。
2. 最小时长过滤：
   - 低于阈值进入 `文件异常` 审查。
3. 响度归一 + 指纹提取：
   - 目标 `-14 LUFS`，在库内滤镜链完成（不依赖 `ffmpeg.exe` 进程）。
   - 失败进入 `文件异常` 审查，并附名称相近建议。
4. 指纹重复决策：
   - `KEEP_EXISTING`：跳过新文件（同时尝试把新文件更优封面信息并入保留曲目）。
   - `REVIEW`：进入歌曲审查组，**不提前入库**。
   - 其它分支：进入归档写库。
5. 归档写库：
   - 归档复制与 `source_sha256` 同步计算（单次读取源文件）。
   - 命中 `source_sha256`：
     - 未删除记录：跳过。
     - 已删除记录：进“已删除歌曲重新导入”审查（延后入库）。
   - 写库后如存在重复候选：执行元数据补全与封面优选合并；必要时软删除旧版本。

## 3. 歌词阶段

1. 读取歌词文本并进行 HTML 反转义。
2. 纯音乐占位歌词：
   - 直接跳过，不再做歌曲匹配，也不再创建“占位未匹配”的审查项。
3. `text_hash` 去重：
   - 命中已删除歌词：进入“已删除歌词重新导入”审查。
   - 未命中：写入歌词存储并建库记录。
4. 歌词-歌曲匹配：
   - 高置信度：自动建立双向映射。
   - 低置信度：进入歌词审查组（带建议歌曲）。

## 4. 审查阶段（UI）

1. 歌曲审查组：
   - 组内独立卡片、独立按钮与组进度条。
   - “保存勾选的文件”：仅对勾选项执行（含延后入库）。
   - “取消导入”：整组忽略。
2. 歌词审查组：
   - 组内独立卡片、独立按钮（无组进度条）。
   - 默认“相同歌词”勾选策略：
     - 判定为同名组时优先行数更多，其次优先括号尾标更少的文件名。
     - 非同名组优先文件修改时间更新者。
3. 所有审查组支持“反选”。

## 5. 用户取消导入

1. 保留进度停止：可后续继续导入。
2. 全量回退停止：删除本次新增记录并清理恢复状态。

## 6. 备注

1. 媒体处理后端已切换为 PyAV（库模式）。
2. 指纹当前为项目内实现；Chromaprint 作为后续可选后端评估项。
