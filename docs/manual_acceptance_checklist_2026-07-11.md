## A. 通用表格编辑

- [ ] A1. 在【歌曲管理】双击标题单元格，修改后按 Enter；内容应保存，终端不出现 `editing failed` 或 `commitData`。
- [ ] A2. 修改艺术家、专辑等字段，切换页面再返回；修改应仍存在。
- [ ] A3. 编辑当前排序字段；提交后歌曲应移动到正确位置，不能写入错误行。
- [ ] A4. 在【歌词管理】编辑标题、艺术家、专辑、作者；Enter 提交和切页后结果均正确。
- [ ] A5. 连续编辑不同表格的多个单元格；不能残留编辑器、错行提交或出现 Qt 编辑警告。完成后点击歌词表头的艺术家、作者等列，混合数字/文字值也不能报排序异常。

## B. 歌词管理多选

- [ ] B1. 启用多选模式，单击或拖动选择多行；所有选中行应持续高亮。
- [ ] B2. 点击【反选】；当前可见结果应正确反选。
- [ ] B3. 批量修改作者；只能修改选中歌词。
- [ ] B4. 批量删除；只能让选中歌词进入回收站。
- [ ] B5. 多选后执行搜索、筛选或排序；依次输入 `201`、`20`、`202` 后，原先选中的 2019、2020、2021 仍应保留；批量操作也应作用于完整 ID 集合。
- [ ] B6. 在编辑模式和多选模式间切换；双击编辑、右键菜单和批量操作应互不冲突。
- [ ] B7. 关闭多选模式后连续点击【反选】至少三次；选择应依次在“全部可见行 / 无选择 / 全部可见行”间切换，不能只在末尾两项间来回跳。
- [ ] B8. 启用多选模式，按住 Ctrl 左键单击作者、标题等可编辑单元格；应立即进入该单元格编辑，原有多选集合不能意外丢失。

## C. 歌词与歌曲审查

- [ ] C1. 打开歌词待审查记录；“库内歌词参考”应显示完整歌词，不再固定只有约 10 行。
- [ ] C2. 绑定文案应显示“当前已绑：歌曲名”，保存时应沿用该绑定。
- [ ] C3. 打开更改绑定窗口；当前绑定歌曲应在搜索结果中自动预选。
- [ ] C4. 初始歌词对比预览区域应较窄，但可拖动扩大。
- [ ] C5. 歌词条目说明应位于歌曲名称和打开按钮下方，横向布局紧凑易读。
- [ ] C6. 歌曲待审查条目也应采用紧凑布局，说明区域易读。

## D. 统计与歌单导入

- [ ] D1. 【统计导入历史】中源文件仍存在的记录，右键【取消导入】应可用。
- [ ] D2. 源文件已移动或删除时，【取消导入】应置灰。
- [ ] D3. 取消统计导入后，只减去该文件贡献；其它来源的播放次数、时长和评分不变。
- [ ] D4. 重复导入相同来源文件或 `playlist_hash`；历史中只保留最新有效记录。
- [ ] D5. 导入数据库位置不匹配的歌单文件；应报错且不创建歌单。
- [ ] D6. 重复导入同名歌单，分别验证【覆盖】和【自动重命名】；自动命名应产生 `(2)`、`(3)`。
- [ ] D7. 歌单导入详情中的成功数、失败数和无法识别歌曲列表应正确。
- [ ] D8. 拉宽【统计导入历史】的源文件路径列；应显示完整路径，不再固定为 `F:…`。对下方【歌单导入历史】执行相同验证。
- [ ] D9. 导入 `E:\GreenSoftware_Workspace\MusePlayer\data\playback_stats.json`；程序应自动读取同目录 `library.json` 完成跨 ID 映射。当前数据预计应用约 2123 首、跳过约 21 首，不能再全部跳过。
- [ ] D10. 查看 D9 的导入详情并执行取消导入；跳过项应有明确数量，已应用的约 2123 首贡献应可完整回退。
- [ ] D11. 对“生效歌曲 0 首”的统计历史执行【取消导入】；应成功移除记录并显示影响歌曲 0 首，不能再提示 `playlist_hash_not_found`。
- [ ] D12. 保留一条同源文件的零首记录后，再成功导入该文件；历史中旧记录应被最新成功记录替换，而不是同时保留两条。

## E. 回收站与排除路径

- [ ] E1. 回收站顶部搜索框输入文件名、标题、艺术家或 ID；左右表格应实时筛选。
- [ ] E2. 清空搜索；全部记录恢复，状态栏显示总数和当前显示数量。
- [ ] E3. 【已排除路径】搜索框输入部分目录或文件名；路径表应实时筛选。
- [ ] E4. 选中路径并点击【删除选中路径】；应出现二次确认。
- [ ] E5. 删除排除路径后重新扫描对应目录；文件应能再次进入导入或审查。
- [ ] E6. 导入运行期间删除排除路径；任务结束后刷新，该路径不能被旧状态重新写回。

## F. 导入去重与待审查队列

- [ ] F1. 同一音频复制到两个不同路径后导入；不能产生两条正式歌曲或两条等价审查项。
- [ ] F2. 第一份音频进入待审查后，再导入相同或近似音频；必须同时检查待审查队列。
- [ ] F3. 新版本质量更低；应跳过新文件并保留旧审查项。
- [ ] F4. 新版本质量明显更高；旧审查项应变为已忽略，新版本继续正式导入或进入必要审查。
- [ ] F5. 相同内容的不同格式即使指纹摘要相同，也应比较质量，而不是无条件保留旧项。
- [ ] F6. 相似度处于人工审查区间；新审查项应关联旧 `review_id` 和旧路径，不能自动删除任一版本。
- [ ] F7. 旧审查项缺少艺术家或专辑、新文件包含有效标签；保留旧项时应补齐空缺标签。

## G. 基础回归

- [ ] G1. 执行 `uv run musearc ui`；歌曲、歌词、导入管理和回收站页面均可正常打开。
- [ ] G2. 播放歌曲后执行移动、删除或恢复；播放器占用应自动释放。
- [ ] G3. 歌曲和歌词搜索验证实时搜索、清空按钮、Esc 清空和 Ctrl+Z 撤回。
- [ ] G4. 设置中关闭实时搜索后，应按 Enter 或搜索按钮才执行查询。
